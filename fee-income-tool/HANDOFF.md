# 대학원 전형료 수입처리 자동화

광주은행에 들어온 전형료 입금을 읽어 → 지원자를 찾아 → 수입처리 엑셀을 만들고 →
교내 ERP에 수입결의서를 올리는 과정을 자동화한다.

호출어: **"전형료 수입 자동으로 잡는거"**

---

## 한 줄 실행

```powershell
powershell -ExecutionPolicy Bypass -File C:\projects\fee-income-tool\run.ps1
```

입금일을 직접 주려면 `-Day 2026-09-01`, 은행 읽기를 건너뛰려면 `-SkipBank`.

---

## 사전 준비 (한 번만)

크롬을 **원격디버깅 모드**로 띄우고, 그 창에서 사람이 직접 로그인한다.
비밀번호·인증서는 이 도구가 절대 다루지 않는다.

```powershell
& "C:\Program Files\Google\Chrome\Application\chrome.exe" `
  --remote-debugging-port=9222 --user-data-dir=C:\chrome-debug-profile
```

그 창에서 열어 둘 것:

1. **광주은행** 빠른서비스 → 계좌관련조회 → 거래내역조회 → 해당 계좌 조회한 상태
2. **U-ERP** → 로그인 → 수입결의서 작성 화면

## 처리 단계

| 단계 | 파일 | 하는 일 |
|---|---|---|
| 1 | `bank_read.js` | 크롬(9222)의 은행 탭에서 입금 건과 화면 캡쳐를 읽는다 |
| 2 | `match_payer.py` | 통장 입금자명(영문, 10자로 잘림)을 지원자 명단과 대조 |
| 3 | `prep.py` | 캡쳐를 기존 서식과 같은 모양으로 자르고, 입금일 문구·수입결의일 계산 |
| 4 | `make_income.ps1` | 수입처리 엑셀 생성 (서식 복사 → 인원수만큼 행 확장 → 캡쳐 삽입) |
| 5 | `erp_income.js` | ERP 수입결의서 작성·첨부·결의신청 *(작성 예정)* |

## 수입결의일 규칙

입금일 기준으로 잡되,

- 평일(월~목) 입금 → **그날**
- **금요일** 입금 → 다음 **월요일**
- **토요일** 입금 → 다음 **화요일**
- **일요일** 입금 → 다음 **화요일**

공휴일은 아직 반영하지 않는다. 결의일이 공휴일이면 사람이 판단한다.

## 이름 대조 방법

통장에는 영문명이 10자로 잘려 찍힌다(`ZHOU ZHONGLAI` → `ZHOUZHONGL`).
그래서 **영문명을 공백·기호 없이 대문자로 만든 뒤 앞부분이 같으면 같은 사람**으로 본다.
후보가 둘 이상이거나 없으면 멈추고 사람에게 묻는다 — 임의로 고르지 않는다.

대조에 쓰는 자료(앞에 있는 것부터):

1. `★20260901 기준 외국인 유학생 재학생 통계(학번 기재).xlsx` 의 `전형료 입금확인` 시트
2. `2026학년도 후기 대학원 지원자 전형료 납부현황(39명).xlsx` 의 `전형료 납부현황` 시트

학기가 바뀌면 `match_payer.py` 의 `SOURCES` 를 새 파일로 바꾼다.

## 수입처리 엑셀 서식

`template/form_base.xlsx` — 실제 파일(`대학원 전형료 수입처리(20260814).xlsx`)을 그대로 복사한 것.

- 인원이 여럿이면 **합계 행 바로 위에 행을 끼워 넣어** 서식이 그대로 따라오게 한다.
- 합계는 `=SUM(F5:F{마지막})` 수식으로 다시 쓴다.
- 캡쳐는 표 아래에 원본과 같은 크기(603 × 217.8pt)로 넣는다.
- **검증됨**: 3명짜리로 만든 결과가 실제 `20260821` 파일과 값·병합·수식까지 일치.

> PowerShell 5.1 은 `.ps1` 을 ANSI 로 읽어 한글 문자열을 깨뜨린다.
> 그래서 스크립트에는 한글을 절대 넣지 않고, 한글은 전부 UTF-8 데이터 파일에서 읽는다.
> (`dest_path.txt`, `name_pattern.txt`, `data/date.txt`, `data/payers.tsv`)
