# 작업일지 자동 작성·저장

"일지 써줘" 한마디로 ①일지 작성 ②git 커밋·푸시 ③노션 상세 업로드까지 전부 끝낸다.

일지 파일: `C:\Users\user\Desktop\★국제협력처\작업일지_Claude_YYYYMMDD.md` (오늘 날짜)

## 순서

### 1. 일지 작성/갱신
- 오늘 날짜 파일이 **이미 있으면 Read 후 이어 쓴다** (다른 탭 세션이 먼저 쓴 절 번호에 이어서.
  절 번호가 겹치지 않게 마지막 번호 +1부터). 없으면 새로 만든다.
- 다른 탭 세션이 동시에 쓸 수 있으니 **저장 직전에 다시 Read** 해서 충돌을 피한다.
- 형식은 기존 일지와 동일하게: 제목 `# 📋 국제협력처 작업일지 — YYYY년 M월 D일 (요일)`,
  절마다 `## 이모지 N. 제목`, 표·불릿 적극 사용, 맨 끝에
  `*🕐 작성/갱신 시각 · Claude Code (모델명)*` 푸터. Notion 변환기가 지원하는 문법만
  사용(제목 1~3, 불릿, 인용, 표 — 체크박스·코드블록은 피함).
- 내용은 **상세하게**: 무엇을·왜·어떻게, 수치(건수·금액·인원), 파일 경로, 배포 여부,
  미결 과제까지. 이 세션에서 한 작업 전부를 빠짐없이.

### 2. git 커밋·푸시 + 노션 업로드 (한 번에)
```
powershell -ExecutionPolicy Bypass -File C:\projects\tools\auto-worklog.ps1
```
이 스크립트가 자동으로:
- `C:\projects`·`C:\projects\work-notes` 변경분 자동 커밋 + 푸시
- 일지 md를 노션에 업로드 — **notion_upload.py가 변경 감지**: 내용이 바뀌었으면
  기존 노션 페이지를 보관(archive)하고 같은 제목으로 새 페이지 생성(= 갱신),
  같으면 SKIP. 100블록 넘는 긴 일지도 전체 업로드됨.
- 오늘 커밋 기록 페이지 노션 생성

실행 후 `C:\projects\tools\autosave.log` 끝부분과 `notion_pages.json` 을 확인해
푸시·업로드가 성공했는지 검증한다. 실패 시 원인을 확인해 직접 재시도한다
(`python C:\projects\tools\notion_upload.py <md경로>` 단독 실행 가능).

### 3. 결과 보고
- 일지에 추가한 절 목록 (한 줄씩)
- git: 커밋·푸시된 저장소와 커밋 수
- 노션: 업로드 결과 (OK 페이지 URL / SKIP / 실패 사유)
- 작업 완료 타임스탬프

## 참고
- 매시간 예약 작업 GU-AutoWorklog 가 같은 스크립트를 돌리므로, 스킬 실행을 잊어도
  다음 정시에 자동 반영된다. 스킬은 "지금 즉시" 반영하는 것.
- git push 는 사용자 승인된 작업 흐름이다 (2026-08-03 사용자 지시: 일지 작성 시 커밋·푸시·노션 기록까지 자동).
- 과거 세션 맥락은 [[intl-office-worklog]] 메모리와 이전 일지 파일 참조.
