# chrome-x-guard — 크롬 X 누르면 한 번 묻기

크롬은 윈도에서 창의 **X** 를 누르면 묻지 않고 바로 닫는다. 탭이 열세 개든 서른 개든
한 번의 오클릭으로 사라지고, `Ctrl+Shift+T` 로도 되살아나지 않는 일이 있다.
이 가드는 X 클릭을 먼저 가로채 **"이 창을 닫겠습니까?"** 를 묻는다.

## 어떻게 알아보는가

낮은 수준 마우스 훅(`WH_MOUSE_LL`)으로 왼쪽 버튼 누름을 먼저 받는다. 그 자리가
닫기 버튼인지는 좌표로 어림하지 않고, 창에 `WM_NCHITTEST` 를 보내 `HTCLOSE` 라고
답하는지 **창에게 직접 묻는다**. 그래서 화면 배율, 최대화 여부, 크롬 판 갈이와
무관하게 정확하다. (실측: 판별에 0~2ms)

닫기 버튼이면 그 클릭을 삼키고 확인창을 띄운 뒤, **예** 일 때만 창에 `SC_CLOSE` 를
보낸다. 탭 닫기(x), 제목줄, 본문 클릭은 손대지 않는다.

## 안전 장치

| 걱정 | 대비 |
|---|---|
| 다른 프로그램을 잘못 막는다 | 창 class 와 **실행파일 이름**(chrome.exe)을 둘 다 확인. 같은 class 를 쓰는 Electron 앱(VS Code·슬랙)은 건드리지 않는다 |
| 가드가 막혀 클릭이 먹통이 된다 | 창이 80ms 안에 답하지 않으면 **삼키지 않고 통과**시킨다. 막히면 통과가 기본 |
| 확인창 때문에 크롬이 멈춘다 | 확인창에 임자 창을 지정하지 않는다. 가드가 죽어도 크롬은 멀쩡하다 |
| 얼떨결에 Enter | 기본 단추가 **아니오** |
| 훅이 조용히 풀린다 | 4초마다 맥박을 본다. 마우스를 움직였는데 훅에 소식이 없으면 다시 건다 |
| 두 번 실행 | 이름 있는 뮤텍스로 하나만 산다 |
| 확인창이 떠 있는데 또 누름 | 무시한다(확인창이 겹치지 않는다) |

## 끄기 / 켜기

`config.json` 의 `Enabled` 를 `false` 로 두고 가드를 다시 띄우면 아무것도 하지 않는다.
완전히 멈추려면 작업 관리자에서 `pythonw.exe` 를 끝내거나

```
taskkill /f /im pythonw.exe
```

(다른 pythonw 작업도 함께 끝나니 주의). 자동시작을 지우려면
`시작` 폴더의 `크롬닫기확인.vbs` 를 지운다.

```
%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup
```

## 기록

`chrome-x-guard.log` 에 닫음/취소를 남긴다. `--verbose` 를 붙이면 누름마다
좌표·판별·걸린시간을 적는다(문제 추적용).

## 같이 해 두면 좋은 것

크롬 설정 `chrome://settings/onStartup` → **이전에 열어본 페이지 계속 보기**.
이 가드는 오클릭을 막고, 저 설정은 **막지 못한 경우에 되살려 준다**. 둘이 짝이다.
